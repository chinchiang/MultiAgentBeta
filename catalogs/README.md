# 固定版本的標準目錄

應用程式只從此目錄載入資料，不在評估期間連外更新。`manifest.json` 保存每個集合與原始檔的 SHA-256；`source-lock.json` 保存抓取時間、官方 URL 與可用的精確 Git commit。

採用 ASVS 5.0.0 正式 release tag、WSTG 4.2 tag、LLM Top 10 2026 canonical final sources，以及 Agentic 2026。原始資料與衍生 catalog 的授權為 **CC-BY-SA-4.0**，歸屬 OWASP Foundation 與各專案貢獻者；這些內容的授權獨立於工具程式碼的 Apache-2.0。授權原文保存於 `sources/asvs-LICENSE.md` 與 `sources/wstg-LICENSE.txt`，LLM repository README 也明確載明同一授權。依 CC-BY-SA 使用、散布或改編時須保留署名與相同授權。

本地 JSON 的改編包括：正規化成一致欄位、增加版本與來源欄位、替 ASVS 加入名稱空間、替 Agentic 加入版本後綴。ID 與標題由來源擷取；不由模型生成。未自行翻譯官方條文。

| 集合 | 應用程式 ID | 官方原始 ID | 核對 |
|---|---|---|---|
| ASVS 5.0.0 | `ASVS-v5.0.0-8.2.2` | `v5.0.0-8.2.2` | release-tag JSON 與 CSV 全部 requirement ID 集合相等 |
| WSTG 4.2 | `WSTG-v42-ATHZ-04` | `WSTG-ATHZ-04` | 同 tag JSON 與 Markdown checklist 全部 scenario ID 集合相等 |
| LLM 2026 | `LLM03:2026` | 相同 | canonical final 十篇標題與官方 README 十項清單逐一一致 |
| Agentic 2026 | `ASI01:2026` | `ASI01` | 官方 ASI mapping 與正式發布公告十項逐一核對 |

`v5.0.0-*` 是 ASVS 明確相容別名，解析後回傳 `ASVS-v5.0.0-*`。未知版次、未加版本的 WSTG／ASI、虛構章節會被拒絕。LLM 2025 與 2026 分類排序不同；不能把舊 ID 只更換年份。

## 更新及驗證

從專案根目錄執行 `python scripts/refresh-catalog.py` 可在完全離線狀態檢查原始內容摘要、重新擷取與交叉比對；它只在記憶體中重建並回報差異，不寫入任何檔案（有差異時 exit 1）。審核後以 `--write` 改寫 canonical 檔案與 manifest；內容沒變時輸出逐位元組相同，`generated_at` 也不變。輸出固定使用 CRLF，Windows 與 Linux 產生相同雜湊。`--fetch` 才會下載腳本內固定版本的官方來源；不自動追蹤 main。若需要新版本，先審核並修改明確 commit，再對變更做版本審查。

Hash 只能檢測相對於可信 manifest 的變動，不是 OWASP 簽章；整個目錄需和應用程式發行物一起可信交付。`VIBEAUDIT_CATALOG_ROOT` 可讓從原始碼目錄啟動的服務改用另一份經審核的 catalog 目錄（例如測試）；本工具只從原始碼目錄啟動，複製出去的 wheel 會拒絕啟動，這個變數不改變這一點。

## 已記錄的來源差異

- 官方 LLM 2026 landing page 的日期為 8 月 3 日，repository README 為 8 月 4 日；內容明確指向同一 2026 版。此差異不影響本地 ID 核對。
- 舊 `/llm-top-10/` 網頁仍顯示 2025，未用它生成 2026 ID。
- 官方 LLM／Agentic PDF 下載在此環境導向 no-access HTML，未取得 PDF；不宣稱 PDF 與 Markdown 相等，也不把 HTML 保存為 PDF。來源內容以公開官方 canonical repository 與官方公告互證。無登入或存取限制繞過。
- Agentic repository 仍有歷史初稿，不能以 `ASI01` 的舊草稿名稱取代正式發布名稱。此目錄使用官方發布公告與 final LLM2026 的 ASI mapping。
- ASI02、ASI05 的發布公告使用簡稱，JSON 保留正式 mapping 的完整名稱。
- WSTG 4.2 官方 checklist 有 98 列、97 個不同 ID；Buffer Overflow 與 Format String Injection 共用 `WSTG-INPV-13`。本地以同一真實 ID 合併，保留兩個子項名稱與目的，不自創替代識別碼。最終目錄共有 345 + 97 + 10 + 10 = 462 個不同 ID。

這是標準 ID 的完整目錄，不是所有標準要求都已實作測試，也不代表 OWASP 認證。

# Version-pinned standards catalogs

The application loads data only from this directory and never fetches updates over the network during an evaluation. `manifest.json` stores the SHA-256 of every collection and original file; `source-lock.json` stores the fetch time, the official URLs, and the exact Git commits used where available.

It adopts the official ASVS 5.0.0 release tag, the WSTG 4.2 tag, the LLM Top 10 2026 canonical final sources, and Agentic 2026. The original data and the derived catalogs are licensed **CC-BY-SA-4.0**, attributed to the OWASP Foundation and each project's contributors; the licensing of this content is independent of the tool code's Apache-2.0. The license texts are kept in `sources/asvs-LICENSE.md` and `sources/wstg-LICENSE.txt`, and the LLM repository README also explicitly states the same license. When using, distributing, or adapting under CC-BY-SA, attribution and the same license must be preserved.

The local JSON adaptations include: normalizing into consistent fields, adding version and source fields, adding the namespace for ASVS, and adding version suffixes for Agentic. IDs and titles are extracted from the sources; they are not generated by a model. The official texts have not been translated by us.

| Collection | Application ID | Official source ID | Verification |
|---|---|---|---|
| ASVS 5.0.0 | `ASVS-v5.0.0-8.2.2` | `v5.0.0-8.2.2` | The set of all requirement IDs in the release-tag JSON equals that in the CSV |
| WSTG 4.2 | `WSTG-v42-ATHZ-04` | `WSTG-ATHZ-04` | The set of all scenario IDs in the same tag's JSON equals that in the Markdown checklist |
| LLM 2026 | `LLM03:2026` | identical | The ten canonical final titles match the ten-item list in the official README one by one |
| Agentic 2026 | `ASI01:2026` | `ASI01` | The official ASI mapping is checked item by item against the ten items of the official release announcement |

`v5.0.0-*` is an explicitly supported ASVS alias; after resolution it returns `ASVS-v5.0.0-*`. Unknown revisions, unversioned WSTG/ASI, and fabricated sections are rejected. The LLM 2025 and 2026 category orderings differ; an old ID must not be reused with only the year changed.

## Updating and verifying

Run `python scripts/refresh-catalog.py` from the project root to check digests of the original content, re-extract, and cross-compare in a fully offline state; it rebuilds in memory only and reports differences without writing any file (exit 1 when there are differences). After review, use `--write` to rewrite the canonical files and the manifest; when the content is unchanged the output is byte-for-byte identical and `generated_at` stays the same. The output always uses CRLF, so Windows and Linux produce identical hashes. Only `--fetch` downloads the official sources pinned to fixed versions inside the script; main is never tracked automatically. If a new version is needed, first review and modify the pinned commits, then run a version review of the changes.

Hashes can only detect changes relative to a trusted manifest; they are not an OWASP signature. The whole catalog must be delivered in a trusted manner together with the application release. `VIBEAUDIT_CATALOG_ROOT` lets a service started from the source tree use another reviewed catalog directory (e.g. for testing); this tool starts only from the source tree — a copied-out wheel refuses to start, and this variable does not change that.

## Documented source discrepancies

- The official LLM 2026 landing page is dated August 3, while the repository README is dated August 4; the content clearly refers to the same 2026 edition. This discrepancy does not affect local ID verification.
- The old `/llm-top-10/` page still shows 2025; it was not used to generate the 2026 IDs.
- Official LLM/Agentic PDF downloads redirect to no-access HTML in this environment, so no PDF was obtained; we do not claim the PDFs are equal to the Markdown, nor do we save the HTML as PDFs. The source content is cross-checked against the public official canonical repositories and the official announcements. No login or access restrictions were bypassed.
- The Agentic repository still contains historical drafts; the old draft names under `ASI01` must not replace the official release names. This catalog uses the official release announcement and the final LLM2026 ASI mapping.
- The release announcements use short names for ASI02 and ASI05; the JSON keeps the full names from the official mapping.
- The official WSTG 4.2 checklist has 98 rows and 97 distinct IDs; Buffer Overflow and Format String Injection share `WSTG-INPV-13`. Locally they are merged under the same real ID, keeping both sub-item names and purposes, without inventing substitute identifiers. The final catalog contains 345 + 97 + 10 + 10 = 462 distinct IDs in total.

This is a complete catalog of the standard IDs; it does not mean all standard requirements have been implemented and tested, nor does it represent OWASP certification.
